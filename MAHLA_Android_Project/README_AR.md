# مشروع مهلة لأندرويد — ربط الحسابات والتراخيص (نسخة اختبار)

يحتوي المشروع على نسختين مستقلتين عبر Android product flavors: `owner` و`client`، مع واجهات HTML المحمولة وطبقة Android WebView.

## ما تم ربطه

- مشروع Supabase: `gnsyjejhsavjxcrmiupn` (`https://gnsyjejhsavjxcrmiupn.supabase.co`).
- نشر Edge Function باسم `verify-access` للتحقق من جلسة المستخدم وصلاحية المالكة أو وجود ترخيص عميلة نشط. لا توجد مفاتيح `service_role` أو `secret` داخل التطبيق.
- نسخة العميلة: تسجيل الدخول بالبريد وكلمة المرور، إنشاء حساب، ثم استرداد كود الشراء عبر `redeem-license`. بعد التفعيل، يجري التحقق من الترخيص النشط عند فتح التطبيق.
- نسخة المالكة: تسجيل الدخول والتحقق من وجود دور `owner` في `mahla_admins` قبل إظهار التطبيق.
- أضيفت لوحة إصدار أكواد للمالكة تستدعي `issue-licenses` وتطلب البريد والعدد (1–25)، والأكواد الصادرة بخطة `lifetime`.
- ضبط `MAHLA_USER_ID` بعد التحقق من الهوية لتخصيص مساحة IndexedDB المحلية لكل حساب.
- تم اختبار الصياغة النحوية لكل كتل JavaScript المضمنة باستخدام `node --check` دون أخطاء.

## ما لم يكتمل بعد

- لم يتم اختبار تسجيل دخول حقيقي أو استرداد كود حقيقي؛ لم ننشئ حساب عميلة تجريبيًا أو نصدر كودًا فعليًا.
- يجب التأكد من إعداد تأكيد البريد الإلكتروني في Supabase؛ إذا كان مفعّلًا، تؤكد العميلة بريدها ثم تعود لتسجيل الدخول وإدخال كود الشراء.
- مزامنة بيانات التخطيط مع قاعدة البيانات ليست موصولة بعد؛ بيانات المخطط الحالية محلية في IndexedDB.
- التشغيل الكامل دون إنترنت لم يكتمل؛ بعض الخطوط وملفات CSS الخارجية لا تزال تُحمّل من الإنترنت. التحقق من الترخيص يتطلب اتصالًا عند التفعيل وعند إعادة التحقق من الجلسة.
- لم يتم بناء APK هنا لعدم توفر Android SDK وGradle في بيئة العمل. GitHub Actions مُعد لبناء نسختي Debug عند رفع المشروع وتشغيل الـ workflow.
- لم يتم إعداد توقيع Release أو manifest تحديثات نهائي.

## بناء نسختي الاختبار

ارفع مجلد المشروع إلى مستودع GitHub وشغّل workflow `Build MAHLA test APKs` من تبويب Actions أو ادفع تحديثًا. سينتج `ownerDebug` و`clientDebug` كملفات APK تجريبية.

## إعدادات البناء

- Android Gradle Plugin: 8.9.2
- Gradle: 8.11.1
- JDK: 17
- compileSdk / targetSdk: 35
- minSdk: 24


## رابط استعادة كلمة مرور المالكة (مضاف)

- يطلب تطبيق المالكة رابط استعادة عبر `mahla://auth-callback`.
- يلتقط Android الرابط العميق ويعيد فتح واجهة المالكة مع رمز الاستعادة في جزء الرابط (URL fragment).
- يجب إضافة `mahla://auth-callback` إلى قائمة Redirect URLs في Supabase Dashboard > Authentication > URL Configuration قبل إرسال أول رسالة استعادة.
- لم يتم إرسال رسالة بريد أو اختبار الاستعادة فعليًا بعد.
