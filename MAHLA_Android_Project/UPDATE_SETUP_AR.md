# إعداد تحديثات تطبيق مهلة

## ما أُضيف
- فحص إصدار عند فتح التطبيق من ملف manifest منفصل للمالكة والعميلة.
- يظهر تنبيه داخل التطبيق إذا كان `versionCode` في manifest أكبر من الإصدار المثبت.
- زر التنزيل يفتح رابط APK؛ أندرويد يظل مسؤولًا عن طلب موافقة المستخدم على التثبيت.
- ملفات الإعداد: `updates/owner.json` و`updates/client.json`.

## قبل تفعيل التحديثات على GitHub
1. لا ترفعي ملفات manifest إلى الفرع المنشور قبل وجود APK فعلي مطابق لها في GitHub Release.
2. يلزم إعداد توقيع Release ثابت؛ لا تستخدمي توقيع Debug المتغير من GitHub Actions للتحديثات فوق نسخة مثبتة.
3. عند إصدار تحديث جديد، زيدي `versionCode` دائمًا، وحدّثي `versionName` ورابط/ملاحظات الإصدار في ملفي JSON.
4. ارفعي ملفي APK بأسماء `MAHLA-owner.apk` و`MAHLA-client.apk` إلى GitHub Release.
5. اختبري التحديث على جهازين/نسختين قبل إرساله للعميلات.

## حدود النسخة الحالية
- هذا الفحص لا يثبت التطبيق بصمت؛ المستخدم يوافق على تنزيل/تثبيت APK من خلال أندرويد.
- لم يتم إعداد مفتاح توقيع Release أو أسرار GitHub Actions.
- لم يتم رفع الملفات إلى GitHub أو إنشاء Release أو اختبار التحديث الفعلي.
- لم يتم تعديل Supabase أو Auth أو التراخيص أو الجداول أو Edge Functions.
